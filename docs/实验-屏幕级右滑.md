# 实验分支：屏幕级右滑返回（cn4.17-1）

分支 `exp/screen-swipe`　版本 `1.5.0+cn4.17-3`　基于 `19ecbcf`（cn4.17）

> 打包踩了两个坑，都已修好：`-1` 的二进制是旧式 bind 流，设置插件报 `bad bind opcode 0x00`；
> `-2` 退回 arm64 单切片，ElleKit 直接跳过，所有触发器失效。`-3` 恢复 arm64 + arm64e 双切片，
> 两个切片都是链式绑定。做法：`ld` 包装把 `-arch arm64e` 改写成 `-arch arm64`（lld 不认 arm64e），
> 统一开 `-fixup_chains`，再由 `lipo` 包装把 arm64e 切片的 cpusubtype 改成 `0x80000002`。

## 这一版在试什么

「返回上级」不再动视图控制器，改成在 SpringBoard 里往触摸子系统注入一次真实触摸：
屏幕左缘按下 → 向右拖 12 步（约 170ms）→ 抬起。剩下的交给 App 自己的边缘返回手势，
所以走的是原生转场动画，也不需要猜 App 用的是 nav 还是自绘容器。

## 为了排除干扰，摘掉了这些

| 摘除项 | 原因 |
|---|---|
| `system.back` → `notify_post(TGRelayBack)` | 原来的返回入口，不摘就两套机制同时跑 |
| Relay 的 `escape → 公开 pop` 链路 | 同上；代码保留但不再注册通知 |
| Relay 的 `EdgeBack`（强制放行系统边缘返回手势） | 它本身也是一条返回路径，会和注入的滑动抢同一个手势 |

现在按「返回上级」**只有**注入这一条路。注入不生效 = 没反应，没有任何兜底。

## 怎么判断成没成

Relay 在 App 进程里比对页面身份（`TGSwipeStamp`：走 `TGVisibleChain`，把 nav 栈深、
tab 选中项都拼进戳），按下后 0.30 秒、0.70 秒各看一次，变了就回一条 `swipe-moved`。

日志：`/var/mobile/Library/Logs/TriggrSwipe.log`

```
tail -f /var/mobile/Library/Logs/TriggrSwipe.log
```

会看到类似：

```
2026-11-07 13:02:11 +0800 注入开始 mode=1 pref=0
2026-11-07 13:02:12 +0800 页面已变化（mode=1 成功）
```

## 坐标单位

触摸事件的 x/y 有两种约定：0..1 归一化、屏幕点数。默认先归一化（mode=1），
页面没动会自动换点数（mode=2）再试一次，成功的那种记在进程内。

要手动钉死：

```
/var/jb/usr/bin/defaults write com.johndie.triggr SwipeCoordMode -int 2   # 2 = 点数，1 = 归一化
```

写完注销一次（respring）让 SpringBoard 重新读。

## 可能的结果与含义

| 日志 | 含义 | 下一步 |
|---|---|---|
| `页面已变化（mode=1 成功）` | 归一化坐标可用，注入链路通 | 观察各 App 一致性，再决定是否留 |
| `归一化无效 → 点数坐标成功` | 只需把默认单位改成点数 | 改 `TGSwipeCoordMode` 默认值 |
| `两种坐标都没反应` | 注入发出去了但系统没吃 | 换注入后端（`_enqueueHIDEvent:`）或放弃此路 |
| `IOHIDEventSystemClient 创建失败` | SpringBoard 没有 HID 派发权限 | 这条路在当前越狱环境不可行 |
| `IOKit 符号取不到` | 私有符号改名/未导出 | 需按系统版本适配 |
